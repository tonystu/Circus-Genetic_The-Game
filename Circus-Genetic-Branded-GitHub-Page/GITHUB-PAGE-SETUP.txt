CIRCUS GENETIC — BRANDED GITHUB PAGES SETUP
Panta Rhei Productions

WHAT THIS DOWNLOAD DOES
The new index.html becomes the branded homepage.
The included game.html launches the same game that was previously index.html.
The website folder contains the homepage's styling and interactions.
Your existing assets folder, scripts folder, and styles.css are still required.
This is an add-on for the complete split-file game you already uploaded.

1. EXTRACT THE ZIP
Right-click Circus-Genetic-Branded-GitHub-Page.zip and choose Extract All.
Open the extracted folder. Upload its contents, not the ZIP or its outer folder.

2. UPLOAD TO THE SAME REPOSITORY
Open the GitHub repository that contains your game.
Go to its Code tab and the top-level file list.
This is the folder where index.html, styles.css, assets, and scripts already sit.
Click Add file > Upload files.
Drag in these extracted items together:

  index.html
  game.html
  website  (the whole folder, with site.css and site.js inside)
  README.md
  GITHUB-PAGE-SETUP.txt

The ZIP also includes .nojekyll. Keep the existing .nojekyll if already present.
If this hidden file is not visible in Windows, it is not necessary to select it again.

The new index.html REPLACES the old game entry page on purpose.
The included game.html preserves that game entry under a new name.
The new README.md replaces the old repository introduction with a branded one.
If you have separately edited your existing README, upload the other items first
and copy the parts you want from the new README later.

Do not delete or move the existing assets, scripts, or styles.css.
Do not upload a Windows .exe, the old all-in-one HTML, or any of the ZIPs.
Do not put website inside assets, or upload the outer extracted folder.

Use a commit message such as: Add Circus Genetic branded game homepage
Click Commit changes.

3. TURN ON GITHUB PAGES
In the repository, open Settings > Pages.
Under Build and deployment:
  Source: Deploy from a branch
  Branch: main  (or the branch where you uploaded your files)
  Folder: /(root)
Click Save.

If Pages already publishes from main / (root), keep those settings.
If you intentionally publish from a docs folder, place all homepage AND game
files in that same published folder, or switch publishing to the repository root.

Wait for the Pages deployment to finish. Settings > Pages will show the actual
site address and a Visit site button. Use that address to play and share.
The repository's github.com address displays source files, not the live game.

If Pages is unavailable, check your repository visibility and GitHub plan.
GitHub Free supports Pages from public repositories. Private-repository Pages
availability depends on your GitHub plan and organization settings.

4. CHECK THE LIVE RESULT
Open the site address shown in Settings > Pages.
You should see the branded Circus Genetic homepage.
Click Start the Game. It should open game.html and show the amp power screen.
Power on, reach the title menu, and confirm the music and artwork appear.
Check the character selector and seven chapter previews on the homepage.

If the old page still appears, wait for deployment, then press Ctrl+F5.
If a 404 appears, verify index.html and game.html are in the published root.
If the game is blank or lacks artwork, verify assets/, scripts/, and styles.css
still exist beside game.html and retain their original filenames and case.
If the homepage is unstyled, check website/site.css and website/site.js.
There is no build command, dependency installation, API key, or paid service
required by this static package.

5. BRAND THE REPOSITORY'S ABOUT PANEL
On the Code tab, click the gear beside About on the right.
Description suggestion:
  An 8-bit band survival game. Start a band. Survive the gig. Keep the beer off the equipment.
Website: paste the actual site address from Settings > Pages.
Suggested topics: pixel-art, browser-game, rhythm-game, beat-em-up, indie-game
Save changes.

Edit index.html for wording and section content.
Edit website/site.js for character descriptions and chapter preview text.
Edit website/site.css for colors and layout.
The page uses relative paths, so it works under a normal GitHub project URL
without knowing your username or repository name in advance.
